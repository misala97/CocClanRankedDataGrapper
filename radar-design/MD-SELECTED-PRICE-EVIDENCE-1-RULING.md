## Binding corrections for the implementation packet

1. **Truthful price basis:** adjustment behavior is unknown. Reject the proposed `adjustment_basis='unadjusted'` constant. Use explicit unknown/provider-reported basis, mark bar-close semantics, retain bar start/end and provisional state, and avoid presenting a completed bar close as a tick known at bar start. No split-adjustment or return-comparability claim; chartPreviousClose discontinuities alone cannot identify corporate actions. Keep provider and stored regimes separate.
2. **Preserve gaps:** dropping null/invalid bars alone can reconnect the line across missing observations. Retain explicit gaps/breaks and break at closed sessions and incompatible regimes. Handle off-grid live points distinctly. No fabricated data or stitching partial upstream data into a different stored basis.
3. **Align actual data:** the existing detail endpoint returns rolling-window chatter, including hourly 1W buckets. A second endpoint returning only a new price window cannot make those buckets align. The final contract must return bounded chatter for the same window or explicitly adapt the detail request. Preserve correct source/status/config coverage and unknown versus zero semantics; do not relabel hourly counts as 15-minute counts.
4. **Bound resources honestly:** a separate HTTP endpoint separates frontend loading/failure but still uses the same sync web workers. Two simultaneous slow provider calls can occupy both workers. Specify admission/concurrency, real elapsed deadline and release/cancellation behavior with a focused verification. Connect 3.05/read 5 timeouts do not enforce a six-second total deadline. Avoid restarting HA1's deadline-review cycle by stating precisely which clock and resource are bounded.
5. **Cache and traffic:** stable keys must include pinned identity, currency, interval/session policy and window generation; an exact moving `period2=now` defeats reuse. Bound the existing transport cache as well as any new cache. A token bucket allows bursts; '10/min' needs exact semantics. Two historical workers are not a universal deployment fact; process-local caps exclude other processes and ingest. State those limits and account for configured process count/restarts rather than claiming a global provider cap. Ops counters must identify worker/reset scope or aggregate durably; one worker response is not a whole-app total.
6. **Source request and identity:** range=5d evidence does not establish identical period1/period2 behavior. Choose and test the actual request shape used. Reuse exchange/currency checks, but verify mapping rules and Nasdaq MIC aliases (including XNMS) against local code. A provider-specific deterministic symbol transformation with response validation may be appropriate; never rewrite shared mapping or silently guess another instrument. Unknown mappings fall back safely.

These are plan corrections, not instructions for the Researcher to edit application code. Numerical defaults from the return (60s fresh, 15min maximum cache staleness, bounded entries/bytes) are reasonable starting proposals, not yet a complete enforceable specification.
