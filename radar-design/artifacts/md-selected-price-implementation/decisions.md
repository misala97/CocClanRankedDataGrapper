# MD-SELECTED-PRICE-IMPLEMENT-1 — bounded implementation decisions

Routine choices made inside the SPEC/PLAN boundaries (PLAN: "record the decision in the candidate ledger and continue"). None widens the product, adds a dependency, service, schema or provider, or changes HA1, headline, scores, poller, German behaviour, longer spans or the legacy chart.

| # | Decision | Why / boundary kept |
| --- | --- | --- |
| D1 | Pure reducers live in `price_chart_contract.py`, which imports only `analysis_contract` (pure), `market_calendars.us` and `prices.yahoo`. `chatter_tone.reconcile_slot` is imported lazily inside `tone_slots`. | The spawned fetch child imports the contract for normalization; a module-level `chatter_tone` import would pull `extensions`/`models`/Flask-SQLAlchemy into the child. Verified: the real spawned child reports none of flask, flask_sqlalchemy, sqlalchemy, extensions, models, app, auth in `sys.modules`. |
| D2 | `chatter_tone.py` is unchanged. The bounded tone read is `TONE_ROWS` SQL text in the reader, with the classification CASE in `classify_recorded_tone`'s order. | Old caller/tests untouched. Equivalence is tested by running the SQL on SQLite over every attitude × verdict pair and comparing with `classify_recorded_tone`, plus conflict, two-mention, no-post, low-confidence, promoted, non-human-chatter and other-ticker events. |
| D3 | `ChartSqlStore` subclasses HA1's `analysis.SqlStore` and reuses its `_timed` statement-scoped timeout, `_errno` and `ReaderBudget`; HA1 `ContractError` codes are translated (`analysis_limit`→`read_limit`, `analysis_unavailable`→`store_unavailable`). Identity uses HA1's `_eligibility` and `valid_ticker` by reference. | "Reuse HA1's SqlStore technique without editing HA1." No HA1 file changed. |
| D4 | Identity refusals: unknown or delisted company → 404 `unknown_ticker`; zero or two eligible primaries, non-positive IDs → 422 `unsupported_instrument`; market other than `us` → 422; malformed ticker → 400 `invalid_ticker`. | SPEC §3 status classes; "exactly one current mapped US primary". |
| D5 | Chatter identity floor = company `first_seen` (as HA1). Price identity floor = instrument `mapped_at` (quotes by event time, daily closes by modeled regular close). | SPEC §5 "earlier than company/mapping identity floor is unknown"; SPEC §4 "never use … pre-mapping rows". |
| D6 | A 15-minute bucket straddling `window.to` makes its slot partial; a short final slot whose buckets all ended is not partial for that reason alone. Off-grid rows, pre-identity rows, absent represented-source buckets, `missing`/`truncated` statuses and unknown source-slots also make a slot partial. | SPEC §3 "final clipped bucket is partial"; missing is not zero. |
| D7 | A conflicting duplicate or malformed bucket makes that SOURCE unknown for the whole slot (excluded from the sum, slot partial); if no source remains valid the count is null. Bare `reddit` plus any `reddit:*` counted in the same bucket withholds the slot total (`overlap_ambiguous`). | SPEC §5. |
| D8 | `config_transition` is flagged on the slot where a source's config version differs from its previous counted bucket (inside or across slots). Coverage is not downgraded by it. | SPEC §5 "flagged". |
| D9 | Normalization: `None`/non-positive closes become explicit null points; NaN/Inf/strings/booleans reject the whole body as invalid. Every off-grid point is omitted and counted (not only a trailing one). Raw bars > 4,000 or normalized points > 2,000 reject. | SPEC §4 "finite positive values … response limits … null/nonpositive bars become explicit null points". |
| D10 | `provisional` and `at` are decided against the data's RECEIPT instant (`at = min(end, received_at, window.to)`), so a bar captured mid-way stays provisional when served later from cache. | SPEC §4 "a bar timestamp is its start … unfinished bar at=min(now,end)"; `now` read as the acquisition's now. |
| D11 | Line breaks: null value, previous null, missing expected bar, market-state change (pre-market/regular/after-hours) and session change for bars; for stored quotes, a source/basis regime change, a market-state change or a gap over 15 minutes. Every stored daily close is its own dot. | SPEC §4 "never interpolate or draw straight across a missing/null bar"; daily closes have no intraday observations between them. |
| D12 | Stored quote fallback excludes legacy rows without market/MIC, shadow rows, other MIC/currency, rows fetched after the read began, rows fetched before their own event time, rows before the mapping and non-positive prices. With several sources, the source with the latest valid event is used alone and the others are disclosed. A quote or daily read over its bound refuses the fallback (price null + warning) instead of trying the other dataset. | SPEC §4 "one coherent dataset … store overflow refuses the fallback". |
| D13 | Yahoo symbol form: `^[A-Z0-9]{1,10}$` unchanged; exactly one class-share dot `^[A-Z0-9]{1,8}\.[A-Z0-9]{1,3}$` → hyphen. Everything else, including an already hyphenated stored symbol, is refused upstream (stored data only). | SPEC §2 "unknown forms refuse upstream". |
| D14 | Coordinator cooldowns: 5xx/network, timeout, invalid, empty → 60 s for that chart (`backoff`); 404 and identity mismatch → 15 min (`unavailable`); 401/403/429 → provider-wide ladder or longer Retry-After; Retry-After over one day → `unavailable` until the full time with `retry_after_seconds` capped at 86,400 in the answer. An `upstream_error` counter was added beside the SPEC's list. | SPEC §6; identity mismatch given the unsupported window because a wrong listing does not fix itself within a minute. |
| D15 | A stale (60 s–15 min) cached series is served with the admission's own state (`pending` when a refresh was admitted, `backoff`/`busy` otherwise) rather than `ready`. | Keeps acquisition state and price staleness separate. |
| D16 | Fetch child framing: JSON in 64 KiB messages ended by an empty message; the supervisor stops reading and terminates the child the moment the total passes 512 KiB. Bounded transport rejects every cookie (`DefaultCookiePolicy(allowed_domains=[])`), sets `trust_env=False`, `allow_redirects=False`, streams the body with a 512 KiB bound, connect/read timeouts 2 s/3 s. | SPEC §6 channel bound, no cookies/crumbs, no redirects, no inherited credentials. |
| D17 | Process topology note: `multiprocessing` spawn re-imports the parent's `__main__` module in the child when it has a file path. Under gunicorn and `python -m pytest` that is a launcher module; a development server started as `python app.py` would have its unguarded top level executed in the child. Recorded as a limitation, not engineered around. | Production uses gunicorn (release-attributed topology). |
| D18 | 30-second local cache stores the WINDOW it was read for; a reused entry answers with the same `from/to` its counts were read over (price clipped to that `to`). Key: fingerprint, span, session dates, window start, concrete sources. | SPEC §7 cache + SPEC §3 shared window bounds. |
| D19 | Frontend flag travels by React context (`SelectedPriceCharts`) from the shell; `ChartSection` receives `selection` and `visible` from both callers. `TONE_COLORS` in `ChatterHistogram.tsx` is now exported (no behaviour change). | Avoids threading a prop through Chatter/ChatterWorkspace internals; old consumers default to false. |
| D20 | Client refusals `unsupported` (422) and `disabled` (404 feature_disabled) fall back to the original chart; other errors show a chart-local retry, or keep the last answer for the same key with its age. The hook retries a transient failure once. | SPEC §8 "feature-disabled or ineligible market uses the original chart component". |
| D21 | Axis: 1W labels each regular session by its US Eastern date; 1D labels even Berlin hours; the right end reads `now HH:MM` on a live window and `HH:MM session end` otherwise, with the Berlin zone name. Month names are written out (ICU `en-GB` September varies) and day numbers unpadded (Chromium pads with a weekday). | SPEC §2/§8 date labelling. |
| D22 | `tests/test_radar_operations_api.py` exact key set gains `selected_price_ops` (one-line adjacent test update; the suite needs the dev database and was not run). | SPEC §7 additive ops field. |
| D23 | Optional MariaDB fixture proof not attempted: the only MariaDB binary on this machine is inside the protected `C:/Users/michi/.radar-ha1-local-qa`; `C:/Program Files/MySQL/MySQL Server 8.0` is a different engine (and the protected 3306 service's installation). No download. | PLAN optional DB step; protected environments. |
