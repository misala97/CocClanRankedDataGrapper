## 3. Observed semantics the C1 packet can state without inference

- **Endpoints.** Identity: `GET https://paper-api.alpaca.markets/v2/assets/{symbol}` (200 asset object / 404 code 40410000). Bars: `GET https://data.alpaca.markets/v2/stocks/bars?symbols=…&timeframe=1Min|5Min&start=…&end=…&feed=sip&adjustment=raw&sort=asc&limit=…`. Both accept the same two `APCA-API-*` headers.
- **Response shape.** `{"bars": {"<SYMBOL>": [ {c,h,l,n,o,t,v,vw}, … ]}, "next_page_token": null|string}`. No `currency`, `meta`, exchange or timezone in the bars response. Symbol key equals the requested spelling; an unknown symbol simply has no key (HTTP 200, `bars: {}`).
- **Timestamps.** `t` = bar START in RFC-3339 UTC with `Z`; all 4,209 SIP bars observed had whole seconds. DOC reserves nanosecond precision, so the parser must accept fractional seconds. `start` and `end` are inclusive: a bar with `t == end` is returned.
- **Close/adjustment.** `c` is the bar close, numeric, positive in every observed bar; `adjustment=raw` makes the basis explicitly raw (an improvement over Yahoo's unknown basis).
- **Gaps.** Minutes/5-minute slots without eligible trades are absent. No null bar and no zero close exist in this response format, so "no data" is only ever absence, and the contract's `nulls` counter would stay 0 for Alpaca.
- **Closing-minute bar.** A bar at exactly the session close instant (20:00:00Z = 16:00:00 ET) is returned per session for most symbols; it is the closing-auction minute. `price_chart_contract.state_at` classifies that instant as `afterhours`, so today's contract would break the line before it and treat it as an after-hours observation. C1 must decide explicitly whether the modeled regular session should include that minute or label it; nothing is silently wrong, but the choice is visible.
- **Pagination.** A single-symbol 1D (≤ 960 extended minutes, INFER from DOC bounds; 391 observed for the regular session) or 1W (847 observed for AAPL) request returned everything with `next_page_token: null`. The multi-symbol week paginated at ~2.5 k bars / ~256 KiB with `limit=10000`; the cap is undocumented. The adapter must treat a non-null `next_page_token` as "truncated" (disclose or refuse, never silently complete) even though the per-chart shape did not hit it.
- **Delay/clamp.** DOC: Basic SIP requires `end` ≥ 15 minutes old; when `end` is omitted it defaults to now−15 minutes for users without real-time access. The assignment's now−16-minute clamp was respected and never probed; the refusal text "subscription does not permit querying recent SIP data" (code 42210000 in the FAQ example) was not observed.
- **IEX.** `feed=iex` is a partial tape: same shape, far fewer bars for thin listings (FT 5, RZLV 80), different same-minute closes. Only usable as a separately labelled regime, optional for first implementation, never spliced into SIP.
- **Quota.** 200 requests/minute (DOC + `X-RateLimit-Limit` header). 429 semantics documented ("Use the X-RateLimit-... response headers"), not observed.
- **Identity metadata.** Asset object gives symbol, class, exchange (Alpaca names, not MICs), status, tradable, name and margin/borrow fields — no currency, no MIC. Radar's `RadarInstrument` (ticker, mic, currency=USD) stays the identity of record; the asset call can confirm `us_equity` + `active` + exact symbol echo, cached per instrument.
- **Live partial session (not observed).** The run happened after close, so the "current session so far" behaviour — bars up to `end = now−16 min` while the session is open — rests on DOC, not LIVE. The response format has no reason to differ; the clamp is the only moving part. Recorded as a limitation, not an ambiguity that changes the contract.
