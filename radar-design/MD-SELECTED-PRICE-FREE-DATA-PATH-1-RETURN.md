## 4. Details for the candidate that passes documentation after an account: Alpaca Market Data Basic

All DOC unless marked; nothing below was executed.

- **Account/plan state:** none today. A free Alpaca account (paper trading is enough per the docs: "The Basic plan serves as the default option for both Paper and Live trading accounts … zero cost") yields an API key id and secret. Eligibility for a German resident, the exact sign-up data required, and whether paper-only sign-up avoids brokerage onboarding were **not verified** and belong to the owner decision.
- **Request shape (1D, consolidated tape):** `GET https://data.alpaca.markets/v2/stocks/bars?symbols=<provider_symbol>&timeframe=1Min&start=<session 04:00 ET as RFC-3339 UTC>&end=<min(now − 15 min − margin, session close)>&feed=sip&adjustment=raw&limit=10000&sort=asc` with headers `APCA-API-KEY-ID` and `APCA-API-SECRET-KEY`. The `end` clamp is mandatory on Basic: querying SIP data younger than 15 minutes returns the documented refusal "subscription does not permit querying recent SIP data" (a 4xx that Radar's child would classify as throttle/backoff, so the adapter must never ask for it). Optional tail: the same request with `feed=iex` and `end=now` gives IEX-only trades (a partial tape) for the last 15 minutes; it must be a separate regime, never spliced into the SIP line.
- **1W shape:** same endpoint with `timeframe=5Min`, `start` = first of the five modeled sessions' regular open, `end` clamped as above, `feed=sip`; ≤ 5 × 78 bars.
- **Timestamp/bar semantics:** `t` is RFC-3339 with nanosecond precision, the bar's start; bars exist only for minutes with eligible trades (empty array otherwise); `c` is the close of the bar; `adjustment=raw` makes the adjustment basis explicitly "raw/unadjusted" (an improvement over Yahoo's unknown basis). Pre/post-market bars are included in the time range requested (extended-hours coverage exists for SIP; not separately verified).
- **Currency/listing identity:** the bars response carries only the symbol key. Identity must be pinned from Radar's `RadarInstrument` (ticker, mic, currency=USD) plus an assets reference lookup (`/v2/assets/{symbol}`: exchange, class `us_equity`, status, tradable) cached per instrument, or the pinned identity alone with a strict symbol-echo check. Class-share spelling (`BRK.B` vs `BRK-B`) is **not verified** for Alpaca.
- **Regular-session bounds:** Radar's own modeled calendar (`market_calendars.us`, already used by `price_chart_contract.window_for`) defines the window; the provider's bars are clipped to it. Basic's 15-minute exclusion means a live 1D window always ends ≥ 15 minutes before now for the SIP regime; the window label must say so.
- **Null/empty/error behaviour:** no bars → `bars: {SYMBOL: []}` (INFER from the documented response shape; to be confirmed in the first probe); unknown symbol → 4xx error object; SIP-too-recent → documented 4xx refusal; rate limit → 429. Zero is never a price; absence is absence.
- **Representative sample:** none (no account). The first bounded probe after account creation should reuse the EVIDENCE-1 sample (AAPL, GE, SPY, RZLV, BRK.B, nonexistent symbol) plus FT to compare with the saved 64-observation session.
- **Quota/budget:** documented 200 historical requests/minute on Basic, no documented daily cap. Radar's existing per-process limits (≤ 10 child starts per 60 s, ≥ 60 s between starts for the same chart, one child in flight, 60 s fresh / 15 min stale cache) already bound one visible chart to ≤ 1 request/minute/process; two gunicorn workers ⇒ ≤ 2/minute ≈ 1 % of the plan limit.
- **Terms/entitlement:** T&C "Basic market data plan, which is made available at no cost"; "use the Services and Content solely for your own personal and non-commercial purposes"; "making the Services and Content available to others through your own application … you shall provide Alpaca with 30 days advance written notice". The last clause matters if Radar is shown to anyone other than the owner (personal_apps is multi-user in production per project memory); the owner must confirm Radar's audience before relying on the personal-use clause. Alpaca's IEX real-time feed is documented; consolidated SIP is delayed by the 15-minute rule on Basic.
